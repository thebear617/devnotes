这是一个典型的案例级提示词：用户只提出一个调研任务和视频交付要求，Agent 自己拆解搜索、资料整理、脚本写作、素材生成、配音和视频制作流程。主题可以替换为产品、行业、技术、公司或其他需要研究后讲清楚的问题。

下面以视频中的最后一个端到端演示作为具体样例：研究“300 万美元左右的 NVIDIA GB200 NVLink72 AI 机柜，钱到底花在哪里”，最终交付中文 HyperFrames 演讲、中文配音、图片素材、字幕和可直接打开预览的项目文件夹。

## 案例结构

### 使用的 skills

1. **搜索 skill**：检索 NVIDIA 官方资料、产品规格、公开报道和成本估算。
2. **资料读取 skill**：读取 PDF、Office 等资料，整理关键数字和来源。
3. **Edge TTS skill**：将中文演讲稿转换为语音解说。
4. **GPT Image 2 skill**：根据研究内容生成演讲或短视频所需的图片素材。
5. **HyperFrames skill**：用 HTML 动画组织标题页、成本拆解、图片、字幕和语音，生成可直接预览的演讲页面。

视频中还把 PDF、Word、PowerPoint、Excel 等资料处理能力作为可继续扩展的 skill，但没有把它们作为这个最终案例的明确执行步骤。

### 端到端执行链

```text
研究问题
  → 搜索产品资料与价格证据
  → 整理关键数字、来源和不确定性
  → 拆解成本结构
  → 写成面向普通人的中文演讲稿
  → 生成图片素材
  → 生成中文配音
  → 用 HyperFrames 组合页面、动画、图片、字幕和语音
  → 交付可打开预览的完整项目文件夹
```

## 提示词

```text
做一个调研项目：一台英伟达 GB200 NVLink72 的 AI 机柜，钱到底花在了哪里？

要求：
- 做成中文的 HyperFrames 演讲；
- 使用 TTS 配音；
- 使用 GPT Image 2 生成图片素材；
- 关键数字数据必须有来源；
- 不确定的地方写清楚是估算的；
- 长度大约两分钟；
- 需要有字幕显示；
- 不需要渲染视频。
```

## 建议的增强版

视频中的原始提示词很短，真正的效果依赖 Agent 自己继续拆解任务。实际使用时，可以补充下面这版约束，让研究结果更容易复核和复用：

```text
请完成一个端到端的行业调研演讲项目，研究问题是：
一台售价约 300 万美元的 NVIDIA GB200 NVL72 AI 机柜，成本主要花在了哪里？

请连续完成以下工作，不要只给方案：

1. 资料检索
   - 优先检索 NVIDIA 官方产品资料、技术文档和规格说明；
   - 再补充可信的硬件媒体、投行/研究机构或业内公开估算；
   - 为每个关键数字记录来源 URL、资料名称和发布日期；
   - 如果没有公开标价，不得把估算写成官方价格。

2. 数据整理与成本拆解
   - 建立一份资料笔记，列出规格、价格、成本区间、来源和可信度；
   - 将总价拆解为 GPU/CPU/HBM/先进封装、NVLink 与网络互联、液冷/供电/机柜、测试集成、软件与服务溢价等部分；
   - 明确区分“公开披露”“第三方估算”和“根据总价倒推的剩余项”；
   - 对无法确认的数字标注“不确定”或“估算”，并解释不确定性来自哪里。

3. 演讲内容
   - 写一份约两分钟的中文演讲稿，面向不了解 AI 服务器硬件的普通听众；
   - 先解释 GB200 NVL72 是什么，再说明 300 万美元分别花在哪里；
   - 使用容易理解的类比，但不要牺牲数字准确性；
   - 在演讲稿中保留关键数字的来源标记；
   - 同时生成逐句或分段字幕，字幕必须与配音时间轴对应。

4. 多媒体素材
   - 使用 GPT Image 2 生成适合演讲页面的图片素材；
   - 图片应服务于规格说明、成本拆解和工程结构，不要生成无法验证的“真实机柜内部照片”；
   - 使用 TTS 生成自然的中文语音解说。

5. HyperFrames 交付
   - 使用 HyperFrames 生成一个可直接打开预览的 HTML 演讲页面；
   - 页面至少包含标题页、产品规格、成本拆解、关键数字来源、结论和字幕；
   - 将 HTML、资料笔记、成本拆解、演讲稿、字幕、音频和图片素材放在同一个项目文件夹；
   - 本次只需要生成可预览的 HyperFrames 页面，不需要渲染成最终视频。

完成后请检查：
- 所有关键数字是否都有来源；
- 估算是否明确标注；
- 演讲稿、字幕和音频是否内容一致；
- HTML 页面能否直接打开；
- 最终项目文件夹中是否包含完整的可复核产物。
```

## 这个案例值得记住的地方

- **提示词只描述结果，skills 负责补齐能力**：用户没有逐步指挥“先搜索、再写稿、再配音”，而是声明最终交付物和约束。
- **中间产物是项目的一部分**：资料笔记、成本拆解、演讲稿、音频、图片和 HTML 都保留下来，方便复核，而不是只交付一个最终页面。
- **研究与创作分开**：关键数字先找来源并标注不确定性，再进入演讲稿和视觉素材生成，降低“看起来很专业但数字无依据”的风险。
- **HyperFrames 是可编辑的中间层**：先生成 HTML 动画，再决定是否渲染视频，比直接要求模型生成视频更容易检查、修改和复用。
- **“不需要渲染视频”是重要边界**：先交付可预览的页面，缩短执行时间，也保留后续继续调整的空间。

## 可迁移模板

这个结构可以迁移到任何“研究一个复杂问题并交付可展示成果”的任务：

```text
请围绕【研究问题】完成一个端到端项目。

最终交付：
- 【目标受众】能看懂的【语言】【成果形式】；
- 使用【搜索/资料读取 skill】完成资料检索；
- 使用【写作或结构化整理 skill】形成研究结论；
- 使用【图片/语音/视频 skill】生成多媒体素材；
- 使用【页面或演示 skill】组合成可直接预览的项目。

必须满足：
- 关键事实和数字有来源；
- 披露、第三方估算和推断分开；
- 不确定内容明确标注；
- 保留资料、数据、稿件和素材等中间产物；
- 完成后检查内容一致性、来源完整性和最终产物可打开。
```
