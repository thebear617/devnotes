熊窝任务看板在 v0.29.0 状态真源入仓的基础上，把「加任务还要手编数据文件」的最后一步也省掉了：看板 header 新增「➕ 新增任务」按钮，卡片补上「删除」按钮，两个操作都由本地 dev server 直接写回 `src/data/todo-data.ts`，任务清单从此只有一个来源。

## 新增任务弹窗

- 看板 header 新增橙色「➕ 新增任务」按钮（仅本地 dev 可编辑，线上只读不渲染）。
- 弹窗五个字段：看板分类、任务名称、链接（可选）、备注（可选）、目标日期；新建任务一律先进待办，排期走卡片上的「开始排期」。
- 看板分类为自定义样式的下拉：触发按钮与表单输入框同风格，选项列表为白底圆角卡片，选中项橙色加粗带 ✓，点击外部自动收起，替代原生 select 的系统弹出样式。
- 弹窗标题只保留橙色「新增任务」一级字样，字号 20px / 行高 28px，与右侧关闭按钮视觉等高。

## 直接写回 todo-data.ts

- 新增端点 `POST /__todo_file`：add 往对应看板的 items 数组头部插入一行，id 按看板前缀（生活 l / 编程 c / 科研 r）取现有最大值递增；remove 按 id 整行移除。
- 字符串统一 JSON.stringify 序列化，标题 / 备注含单引号、双引号、换行都不会破坏单行格式；空看板的内联 `items: []` 插入时自动展开为多行。
- 卡片「删除」按钮对全部非归档任务开放（confirm 确认），与弹窗新增走同一条写回链路；写盘复用 self-write 抑制窗口，客户端同步内存看板数据保持 UI 即时一致，不闪屏、不丢视图。
- 上一版曾把弹窗任务存进 `todo-state.json` 的 `customItems` 数组，本次整体退役（同步协议字段、渲染合并路径、`todo:validate` 校验全部移除），已有自定义条目迁移为 `l32`。
