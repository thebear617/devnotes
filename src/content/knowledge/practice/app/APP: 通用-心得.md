APP｜插件:
  - 优点：任何地方可见可用
  - 缺点：但是更要注重与操作系统、其他App的联动和适配
网页:
  - 安全系数高｜不用考虑适配
  - 难自适应窗口大小，不能和系统交互

### Web 会话存在的必要性
| 场景 | Web 会话价值 | 本地插件是否足够 |
|---|---|---|
| 接着 VSCode/CodeBuddy/Codex 里已有任务继续做 | 较低 | 足够，且上下文更连续 |
| 重命名、查看历史、双向同步原生会话 | 较低 | 插件模式更合适 |
| 临时开一条干净、没有历史上下文的新会话 | 有价值 | 插件里也可以新建 |
| 不打开插件，只从熊电台快速启动 Agent | 有价值 | 这是 Web 模式最明显的优势 |
| 需要隔离上下文，避免污染原插件会话 | 有价值 | 可以在插件里另开会话 |
| CodeBuddy 插件桥接没启动或异常 | 有价值，可作为备用通道 | 正常情况下插件足够 |
| 从 DevNotes/LifeNotes 当前文章、草稿、选中文本快速发起任务 | 有价值 | 插件会话也能继续，但上下文传递方式不同 |
| 需要尝试另一模型或另一套全新 Agent 配置 | 有价值 | 目前插件新建也能覆盖大部分需求 |
| 多个项目临时并行处理 | 有价值 | 插件会话标签页也能覆盖 |
