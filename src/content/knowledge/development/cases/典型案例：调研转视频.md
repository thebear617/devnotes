# 案例集合

## 案例一：调研 → 视频（Pi Agent + Skills）

### 1. 核心思路

用户只提出调研任务和视频交付要求，Agent 自己拆解搜索、资料整理、脚本写作、素材生成、配音和视频制作全流程。整个流水线依赖 5 个 skills 串联：

1. **搜索 skill**：检索 NVIDIA 官方资料、产品规格、公开报道和成本估算
2. **资料读取 skill**：读取 PDF、Office 等资料，整理关键数字和来源
3. **Edge TTS skill**：将中文演讲稿转换为语音解说
4. **GPT Image 2 skill**：根据研究内容生成演讲所需的图片素材
5. **HyperFrames skill**：用 HTML 动画组织标题页、成本拆解、图片、字幕和语音

执行链：

```text
研究问题
  → 搜索产品资料与价格证据
  → 整理关键数字、来源和不确定性
  → 拆解成本结构
  → 写成面向普通人的中文演讲稿
  → 生成图片素材
  → 生成中文配音
  → 用 HyperFrames 组合页面、动画、图片、字幕和语音
  → 交付可打开预览的完整项目文件夹
```

以下以视频中的演示样例展开：研究"300 万美元左右的 NVIDIA GB200 NVL72 AI 机柜，钱到底花在哪里"，最终交付中文 HyperFrames 演讲。

### 2. 提示词

**基础版（原始提示词）**

```text
做一个调研项目：一台英伟达 GB200 NVLink72 的 AI 机柜，钱到底花在了哪里？

要求：
- 做成中文的 HyperFrames 演讲；
- 使用 TTS 配音；
- 使用 GPT Image 2 生成图片素材；
- 关键数字数据必须有来源；
- 不确定的地方写清楚是估算的；
- 长度大约两分钟；
- 需要有字幕显示；
- 不需要渲染视频。
```

**增强版（附加约束，便于复核和复用）**

```text
请完成一个端到端的行业调研演讲项目，研究问题是：
一台售价约 300 万美元的 NVIDIA GB200 NVL72 AI 机柜，成本主要花在了哪里？

请连续完成以下工作，不要只给方案：

1. 资料检索
   - 优先检索 NVIDIA 官方产品资料、技术文档和规格说明；
   - 再补充可信的硬件媒体、投行/研究机构或业内公开估算；
   - 为每个关键数字记录来源 URL、资料名称和发布日期；
   - 如果没有公开标价，不得把估算写成官方价格。

2. 数据整理与成本拆解
   - 建立一份资料笔记，列出规格、价格、成本区间、来源和可信度；
   - 将总价拆解为 GPU/CPU/HBM/先进封装、NVLink 与网络互联、液冷/供电/机柜、测试集成、软件与服务溢价等部分；
   - 明确区分"公开披露""第三方估算"和"根据总价倒推的剩余项"；
   - 对无法确认的数字标注"不确定"或"估算"，并解释不确定性来自哪里。

3. 演讲内容
   - 写一份约两分钟的中文演讲稿，面向不了解 AI 服务器硬件的普通听众；
   - 先解释 GB200 NVL72 是什么，再说明 300 万美元分别花在哪里；
   - 使用容易理解的类比，但不要牺牲数字准确性；
   - 在演讲稿中保留关键数字的来源标记；
   - 同时生成逐句或分段字幕，字幕必须与配音时间轴对应。

4. 多媒体素材
   - 使用 GPT Image 2 生成适合演讲页面的图片素材；
   - 图片应服务于规格说明、成本拆解和工程结构，不要生成无法验证的"真实机柜内部照片"；
   - 使用 TTS 生成自然的中文语音解说。

5. HyperFrames 交付
   - 使用 HyperFrames 生成一个可直接打开预览的 HTML 演讲页面；
   - 页面至少包含标题页、产品规格、成本拆解、关键数字来源、结论和字幕；
   - 将 HTML、资料笔记、成本拆解、演讲稿、字幕、音频和图片素材放在同一个项目文件夹；
   - 本次只需要生成可预览的 HyperFrames 页面，不需要渲染成最终视频。

完成后请检查：
- 所有关键数字是否都有来源；
- 估算是否明确标注；
- 演讲稿、字幕和音频是否内容一致；
- HTML 页面能否直接打开；
- 最终项目文件夹中是否包含完整的可复核产物。
```

### 3. 注意事项

<ol>
<li>
<span class="tip-label">提示词只描述结果，skills 负责补齐能力</span>
<div class="tip-detail">

用户不需要逐步指挥"先搜索、再写稿、再配音"，只需声明最终交付物和约束。Agent 根据自己的 skills 自主拆解步骤。这意味着写好这类提示词的关键不是写得细，而是把交付标准写清楚。

</div>
</li>
<li>
<span class="tip-label">保留所有中间产物，方便复核</span>
<div class="tip-detail">

资料笔记、成本拆解、演讲稿、音频、图片和 HTML 都留在项目文件夹中，而不是只交付一个最终页面。这对于研究型任务尤其重要——如果有人质疑某个数字，可以直接追溯到来源。

</div>
</li>
<li>
<span class="tip-label">先交付可预览页面，不急着渲染视频</span>
<div class="tip-detail">

HyperFrames 生成的 HTML 页面是可编辑的中间层。先确认内容、数据、字幕都正确，再决定是否渲染成视频。这个边界约定能大幅缩短迭代周期，也保留后续继续调整的空间。

</div>
</li>
</ol>

### 4. 使用建议

- **提示词只锁交付标准，不锁执行路径**：这条提示词的核心竞争力在于"声明结果而非过程"——越是不 micro-manage，Agent 越能发挥 skills 的组合能力。
- **研究与创作分开**：关键数字先找来源并标注不确定性，再进入演讲稿和视觉素材生成。这降低了"看起来很专业但数字无依据"的系统性风险。
- **Skills 是可插拔的**：5 个 skills 并非固定组合。如果不需要配音，去掉 TTS skill 即可；如果需要图表，换一个图表 skill。把 skills 理解为乐高块，提示词是拼装说明书。
- **可迁移骨架**：任何"研究一个复杂问题并交付可展示成果"的任务都能套这个结构：

```text
请围绕【研究问题】完成一个端到端项目。

最终交付：
- 【目标受众】能看懂的【语言】【成果形式】；
- 使用【搜索/资料读取 skill】完成资料检索；
- 使用【写作或结构化整理 skill】形成研究结论；
- 使用【图片/语音/视频 skill】生成多媒体素材；
- 使用【页面或演示 skill】组合成可直接预览的项目。

必须满足：
- 关键事实和数字有来源；
- 披露、第三方估算和推断分开；
- 不确定内容明确标注；
- 保留资料、数据、稿件和素材等中间产物；
- 完成后检查内容一致性、来源完整性和最终产物可打开。
```
