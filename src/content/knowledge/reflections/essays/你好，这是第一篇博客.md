## 一、欢迎来到 Thebear 的 DevNotes 博客

这是 devnotes 从 Vue 3 迁移到 Astro 后的第一篇博客文章，
后续会在这里记录更多技术相关的博客文章。之前笔记中心的文章都是用 **HTML 字符串** 嵌在 JS 数据文件里写的，现在：

1. **纯 Markdown**：文章用Markdown语言编写，支持完整的 Markdown 语法
2. **内容集合**：通过 Astro Content Collections 管理，新建一篇文章只需要在 `src/content/knowledge/` 下新建一个 `.md` 文件
3. **MDX**： 可以用**MDX**=Markdown + JSX，让我在 .mdx 文件里直接写 React/Vue/Astro/Svelte 组件，把"文档"和"交互"合在一起。

## 三、知识库的分类方式

DevNotes 把所有文章放进同一个「知识库」内容集合中。`knowledge` 是统一入口，不是分类本身；真正的零级分类先按内容来源与用途分成绿色和紫色两组，再用 frontmatter 和子文件夹分别解决页面浏览与本地归档的问题。

| 层级 | 当前内容 | 作用 |
| --- | --- | --- |
| 内容入口 | 知识库 `knowledge` | 网站里的统一内容入口，对应 `src/content/knowledge/` |
| 零级分类 | 绿色「个人知识积累」；紫色「Agent Work 案例与提示词积累」 | 先区分内容的来源与用途 |
| 一级分类 | 绿色：编程、科研、随想；紫色：Vibe Coding | 页面主筛选，由每篇文章的 `category` 决定 |
| 二级分类 | 基础、综述、实践、方法、AI、PPT、视频、图表、网页、随笔等 | 页面次级筛选，由 `secondaryTag` 决定 |
| 子文件夹 | 按一级分类内部的知识结构继续整理 | 帮助本地阅读和维护，不直接决定页面标签 |

绿色标签对应自己持续学习、理解和记录下来的知识观察；紫色标签对应收集、整理和复用的 Agent Work 案例与提示词。两者都进入同一个知识库，但阅读目的不同：前者帮助建立自己的知识体系，后者帮助直接提升开发与知识工作的效率。

当前文件结构如下：

```text
knowledge/
├── programming/                         # 绿色：编程
│   ├── foundations/                      # 操作系统、网络、数据结构、算法、开发风格
│   ├── traditional-full-stack-development/ # 传统全栈开发
│   └── ai-full-stack-development/        # 智能体工作等 AI 原生开发主题
├── research/                             # 绿色：科研；当前仍保持扁平
├── reflections/                          # 绿色：随想
│   ├── building-guides/                  # 仪表盘、个人博客等搭建指南
│   └── essays/                           # 随笔、观察与个人表达
└── vibe-coding/                          # 紫色：使用 Agent 协作完成开发与工作任务
    ├── awesome-awesomes/                 # 精选的 Skills、Rules、Blogs、Chores、Tricks
    ├── principles/                       # Coding Agent 的公开工作机制与方法论
    └── vibe-working/                     # 网页、图表、PPT、视频等可复用的知识工作流
```

子文件夹的原则是：**只有当一个一级分类内部已经形成稳定的主题群时才继续拆分**。例如，编程按基础、传统全栈和 AI 全栈拆分；随想按搭建指南与随笔拆分；Vibe Coding 按精选资源、原理与实际工作流拆分。科研仍保持扁平，等主题自然聚集后再建立子文件夹。

因此，新增文章时先确定它服务哪个一级分类和二级标签；只有需要在本地文件树中长期聚合的一组主题，才用子文件夹表达。
