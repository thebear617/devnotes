# 纯前端开发

用 Agent 做**纯前端/静态站点**开发的打法：不涉及后端，产出物是能在浏览器跑的 HTML/CSS/JS（或 Astro 等静态构建站点）。这类任务边界清晰、可验证（本地起服务 + 浏览器检查），非常适合 Agent 全流程完成。

## 核心思路

- **数据驱动优先**：前端板块的"内容"优先做成静态数据文件（JSON/JS），Agent 负责生成数据 + 写渲染，解耦且可重复更新
- **先打通外部数据源**：若功能依赖外部数据（API/爬虫），先验证数据可达、格式清楚，再设计页面
- **本地可验证**：`npm run dev` + 浏览器实际检查，别只看代码"应该没问题"
- **沉淀脚本与 skill**：把"拉数据/生成数据/外号映射"等一次性操作固化成脚本，甚至封装成 skill，后续更新零成本

## 案例集合

### 案例一：熊窝英雄联盟板块重构（2026-08-01）

把一个"手工维护的 34 英雄攻略"升级为"RESG 实战数据驱动的全 173 英雄速查"，单次会话完成，**43 条请求、230 积分**（DeepSeek V4 Flash）。

- 打通外部数据源：RESG（海克斯大乱斗数据站）公开 API，CORS 开放，服务端直连抓取海克斯/装备/胜率
- 重构为数据驱动：新增英雄索引、海克斯推荐、外号/拼音表三个数据文件 + 两个生成脚本（`fetch-lol-all.py` / `gen-nicknames.py`）
- 交互层：英雄详情抽屉、外号/拼音搜索、定位筛选、胜率/热度排序、下拉浮窗工具栏
- 踩坑：macOS 大小写不敏感文件系统下 `git add` 通配符不生效（须显式路径）、子路径部署下返回链接用 `../` 会 404（须写 `../index.html`）
- 沉淀：更新流程写入站点 README + 封装全局 Skill（`lol-data-update`），后续数据更新只需跑脚本

## 成本观察

一个"中等复杂度前端功能板块"（含数据打通 + 页面 + 交互 + 部署）全量开发，成本量级在 **200–300 积分**。缓存命中率是省成本的关键——长会话内复用已读文件、重复的构建/验证命令能大幅压低积分。

## 注意事项

- 优先本地起服务验证，而不是只看静态代码
- 外部数据源务必先验证 CORS / 可达性再动手
- 涉及文件系统/路径的处理要留意平台差异（macOS 大小写不敏感等）
- 完成后把"数据更新/生成"流程固化成脚本 + 文档，别让维护依赖记忆
