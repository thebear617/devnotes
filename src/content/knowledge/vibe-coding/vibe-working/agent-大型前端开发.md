# 案例：熊窝英雄联盟板块重构

在 [熊窝 personal 站点](/personal/) 完成了一次从手工攻略到 RESG 实战数据驱动的完整板块重构，最终结算：**43 条请求、230 积分、DeepSeek V4 Flash**。

## 1. 这次做了什么

单次会话内完成了一个功能板块从"雏形"到"完整可用"的全流程：

- 打通外部数据源（RESG 海克斯大乱斗数据站）的公开 API，抓取全 173 英雄的海克斯/装备/胜率数据
- 重构为全英雄数据驱动，新增英雄索引、海克斯推荐、外号/拼音表三个数据文件 + 两个生成脚本
- 新增英雄详情抽屉（RESG 海克斯推荐展示）、外号/拼音搜索、定位筛选、胜率/热度排序、下拉浮窗工具栏
- 处理 macOS 大小写不敏感文件系统的 git 陷阱、修正子路径部署下的返回链接 404
- 沉淀数据更新流程到 README + 全局 Skill，补充开发时间线

## 3. 为什么这么省

- **缓存命中率高**是核心：长会话内大量复用已读过的文件内容、重复的构建/测试命令，这些命中缓存的 token 不重复计费，把成本压到很低
- **单会话连续开发**：尽量在同一个会话里推进一个完整板块，避免反复加载上下文、重开会话造成重复计算
- **命令复用**：构建、数据拉取、验证脚本用一次定义后多次调用，减少重复输出

## 4. 可迁移结论

- **一个"中等复杂度前端板块"的全量开发，成本量级在 200–300 积分**，用 DeepSeek V4 Flash 很划算
- **缓存命中的价值被低估**：长会话里主动保持上下文复用（不轻易重开、复用文件读取结果），能显著降低积分消耗
- **把"外部数据源 + 生成脚本"沉淀成 skill**，让后续同类开发（或数据更新）不用从零摸索，进一步省成本
